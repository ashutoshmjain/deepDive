## Part A — Rewrite the 1-Prompt Setup in the mdIngest README

### A1. Rewrite the install prompt to cover the four verified gaps

- **Where:** mdIngest `README.md`, the "1-Prompt Setup for Antigravity & AI Assistants" section at `:121–137` (verified at head `cc45e1b`). The current prompt is 7 steps. Its step 5 covers only the Windows Drive mount and otherwise says "ask the user for the folder"; it never installs rclone, never installs the Python packages, never mentions ffmpeg, and never sets up DDMA or Beats.
- **Finding (verified at this head):** four gaps, each confirmed against the repos at these heads.
  - (a) Linux/WSL rclone is missing. Google offers no Drive client for Linux, so rclone is the only mount on Linux/WSL, and in Docker/VM there is no desktop app in a container. The current prompt's step 5 only names the Windows mount (`G:\My Drive\dd_hub`) and otherwise says "ask the user". The mdIngest README's own Linux section (`:84–96`) already documents the rclone install, remote config, mount with `--drive-root-folder-id`, `--vfs-cache-mode full`, the `DD_HUB_ROOT` persist step, and the no-FUSE `rclone copy` fallback — the prompt must carry all of it. On WSL the prompt must prefer a native Linux rclone mount over `/mnt/g` (the Windows Drive mount is slow through the WSL 9P bridge, especially for ffmpeg); `/mnt/g` is the fallback only.
  - (b) Python packages are never installed. The current prompt verifies the toolchain but never runs pip. The packages exist and are required: mdIngest `ui/requirements.txt` (verified at `cc45e1b`: `faster-whisper==1.2.1`, `av==14.2.0`, `openai-whisper`, `numpy`) and ddma `requirements.txt` (verified at `d9a6e26`: `openai-whisper`, `requests`, `typer`, `pillow`, `numpy`, `google-generativeai`, `pyyaml`, `faster-whisper==1.2.1`, `av==14.2.0`, `manim==0.22.0`). The mdIngest README's Dependencies table (`:55–65`) claims "Zero pip dependencies (built with pure standard library)" — that is true only for the server's top-level imports (`ui/server.py:8–27` are stdlib-only). Transcription needs the packages: `faster_whisper` is imported lazily inside `run_faster_whisper_transcription` (`ui/server.py:998`) and called from the auto-transcription path (`ui/server.py:3387`). The server starts without the packages but transcription fails without them. The prompt must install both requirements files.
  - (c) ffmpeg is never mentioned. It is essential for the pipeline (the Curator compiles audio and video with it) and the current prompt never verifies or installs it.
  - (d) DDMA and Beats are never set up. The current prompt is mdIngest-only. The workspace needs all three servers: the Curator on `:8000` (ddma `scratch/run_curator.py`, verified in the ddma README's Setup section at `:74–88`) and Beats Studio on `:8001` (ddma `beats_server.py`, verified to exist at the ddma repo root at `d9a6e26`; launched from the landing page's "Launch Beats Studio" button).
  - (e) The current prompt's build step is wrong about the directory. Its step 2 says to build "in the `crate/` directory using `cargo build --release`". There is no manifest in `crate/` (verified: `crate/Cargo.toml` returns 404 at `cc45e1b`). The manifest is the repo-root `Cargo.toml` (verified at `cc45e1b`: package `md-publish`, `[[bin]]` path `crate/src/main.rs`). The build must run from the mdIngest repo root, not inside `crate/`.
  - (f) The current prompt's book.toml verification is wrong. Its step 3 says to verify that `book.toml` contains the `[preprocessor.katex]` and `[preprocessor.ingest]` blocks. The repo-root `book.toml` (verified at `cc45e1b`) contains NEITHER block by design — it says "No preprocessors enabled for the manual build to ensure CI stability." A fresh clone fails that verification. The prompt must not require those blocks in the root `book.toml`; it must verify the built binary exists instead.
- **Fix:** Replace the entire prompt code block at `README.md:121–137` with the rewritten prompt below, VERBATIM. Do not paraphrase it, do not shorten it, do not change a command. The prompt uses the words "workspace folder" for the user's Drive folder throughout and names the environment variable `DD_HUB_ROOT` only where the exact variable is required (the code reads that variable). It does not explain the workspace internals — it tells the assistant what to do.
- **Rewritten prompt (paste exactly):**

```text
Please set up and verify the complete publishing environment (mdIngest + DDMA) in this workspace. Do every step below in order. Do not skip a step. If a step fails, fix it and continue — do not stop and ask unless a step explicitly says to ask.

1. Verify the toolchain: Python 3.10+, Cargo/Rust, mdbook (v0.5.0+), and mdbook-katex are installed and available on PATH. If mdbook or mdbook-katex are missing, install them via `cargo install mdbook mdbook-katex`.
2. Install the Python packages for mdIngest: from the mdIngest repo root, run `pip install -r ui/requirements.txt` (faster-whisper, av, openai-whisper, numpy — required for transcription; the server starts without them but transcription fails).
3. Install the Python packages for DDMA: from the ddma repo root, run `pip install -r requirements.txt` (faster-whisper, av, manim, google-generativeai, pyyaml, and the rest).
4. Verify ffmpeg is installed and on PATH (`ffmpeg -version`). If it is missing, install it (Windows: `winget install ffmpeg` or `choco install ffmpeg`; macOS: `brew install ffmpeg`; Linux: `sudo apt install ffmpeg` or the distro equivalent). The pipeline cannot compile audio or video without ffmpeg.
5. Build the md-publish preprocessor binary from the mdIngest repo root using `cargo build --release` (the manifest is the repo-root `Cargo.toml`; the binary source is `crate/src/main.rs` — do NOT run the build inside `crate/`, there is no manifest there).
6. Verify the built binary exists at `target/release/md-publish`. Do NOT require `[preprocessor.katex]` or `[preprocessor.ingest]` blocks in the repo-root `book.toml` — that file intentionally has no preprocessors enabled (for manual-build stability); the preprocessor is wired in at publish time.
7. Set up the workspace folder. The user creates an empty folder on Google Drive to be the workspace (ask the user for the folder, or use the folder ID from its Drive URL `https://drive.google.com/drive/folders/<FOLDER_ID>`). Then mount it as a local path — the code only does local file I/O against a local path, never the Google Drive web API:
   - On Windows or macOS: use Google Drive for Desktop. Install it and sign in if it is not already installed. The mount appears at `G:\My Drive\` on Windows, or `~/Library/CloudStorage/GoogleDrive-<email>/My Drive` on macOS. Do NOT use rclone on Windows or macOS.
   - On Linux or WSL: use rclone (Google offers no Drive client for Linux). Install rclone, run `rclone config` to create a Drive remote named `gdrive` (complete the browser sign-in), then mount only the workspace folder by its ID: `rclone mount gdrive: /mnt/gdrive/workspace --drive-root-folder-id <FOLDER_ID> --vfs-cache-mode full --daemon`. On WSL, prefer this native Linux mount over `/mnt/g` (the Windows Drive mount is slow through the WSL bridge, especially for ffmpeg); use `/mnt/g/My Drive/<folder>` only as a fallback if the rclone mount is not possible. If `rclone mount` is not possible at all (no FUSE), use `rclone copy` instead: keep a plain local folder, set the workspace path to it, and copy files to/from Drive with `rclone copy` (pull before working, push after).
   - In Docker or a VM: use rclone as on Linux (there is no desktop app in a container).
   - Create the folder structure inside the mounted workspace folder if any are missing: `episodes/`, `vault/`, `inputs/`, `audio/`, `video/`, `mosaics/`, `manims/`, `rules/`.
   - Set the `DD_HUB_ROOT` environment variable to the mounted workspace path and persist it (shell profile, systemd unit, or Docker entrypoint) so it survives new shells.
8. Set up settings: create `<workspace>/vault/settings.json` from `settings.template.json` (in the mdIngest repo root) if it does not exist. Fill in API keys only if the user provides them; never commit settings.json. If the user already has a settings.json in an existing workspace folder, copy that file into the new workspace folder's `vault/` instead of creating one from the template.
9. Launch the mdIngest Publishing Cockpit server (`python ui/server.py` from the mdIngest repo, or `./start_ui.bat` on Windows) on http://localhost:8088 and verify that http://localhost:3000 is accessible via `mdbook serve`.
10. Launch the DDMA Clip Studio (Curator) server: from the ddma repo root, run `python scratch/run_curator.py` and verify http://localhost:8000/curator.html loads.
11. Launch Beats Studio from the mdIngest landing page (http://localhost:8088/, the "Launch Beats Studio" button) and verify http://localhost:8001 responds.
12. Verify: `DD_HUB_ROOT` resolves, the workspace folder structure exists, `episodes/<N>/plan.json` is readable for an existing episode (or the workspace folder is empty for a fresh workspace), and all three servers respond (cockpit :8088, Curator :8000, Beats :8001).
```

- **Verify:**
  1. The prompt code block in the README matches the text above exactly (diff the block against this spec — zero differences).
  2. Every file and command the prompt names exists at these heads: `ui/requirements.txt`, `settings.template.json`, `Cargo.toml` (repo root, package `md-publish`, binary path `crate/src/main.rs`), and `book.toml` in mdIngest (all verified present at `cc45e1b`); `requirements.txt`, `scratch/run_curator.py`, and `beats_server.py` in ddma (all verified present at `d9a6e26`). Confirm `crate/Cargo.toml` does NOT exist (there is no manifest in `crate/` — the build runs from the repo root) and the repo-root `book.toml` contains NO preprocessor blocks (by design).
  3. The prompt names rclone ONLY for Linux/WSL/Docker/VM and explicitly forbids it on Windows/macOS. The prompt names `/mnt/g` ONLY as a WSL fallback, with the native rclone mount preferred.
