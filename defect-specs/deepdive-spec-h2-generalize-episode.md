## Context (verified in code at deepDive 3c179f8; re-verify at the pulled head — paths and names may have moved)

The H2 Manim wiring (design + render + Patch) is locked to episode 249 by explicit refusals, not by structure. Everything else is already episode-generic: the design endpoint builds its paths from the episode number (`projects/<project_id>/plan.json`, `clips/<ep>-<clip>-infographic.mp4`, `clips/<ep>-<clip>-manim.mp4`), the episode-page equation catalog is fetched by episode number, and the composite footer center (N/total) is threaded from the plan (250 already reads "N/14"). The lock is in four places:

1. Beats Studio server (`ddma/beats_server.py`): `H2_EPISODE = "249"` plus a guard (`_h2_refused`) that refuses any other episode ("H2 wiring serves episode 249 only"). The design worker posts to the curator endpoint with the episode.
2. The `/api/beats/manim_retrigger` per-clip handler (same file): it only builds the design body (`force_regen` + transcript + title + directive) when the episode equals `H2_EPISODE` — for any other episode it posts an empty body to the curator endpoint, so the directive and the force flag never arrive. That branch must become episode-generic too.
3. The design endpoint (`ddma/scratch/run_curator.py`, `/generate-manim-infographic`): a hard refusal for any episode other than 249 (HTTP 400, "Refusing: this endpoint serves episode_249 only"). The fresh-design branch also hardcodes the catalog fetch to episode 249 (`fetch_episode_equations("249")`) and gates on `== "episode_249"`.
4. Patch (`ddma/beats_server.py`, `_h2_patch_clip_249`): hardcodes the 249 plan path, the frame assets (`chrome_249.png`, `strip_249.mp4`), the infographic filename (`249-<n>-infographic.mp4`) and the 249 master. Patch for 250 does not exist yet.

Consequence today: "Design this clip" for 250-1 is enabled in the UI but the endpoint refuses it with a 400 — the button does not know about the lock, the server does. Episode 250 has no Manim designs at all (no `infographic_scenes` for any of its 14 clips), because the design step was never run for it and cannot run until this lock is gone.

## The fix

- **Beats Studio guard:** generalize the H2 wiring to accept the episode as a parameter (the episode currently selected in Beats Studio). Remove the 249-only refusal (`_h2_refused`). The design worker passes the selected episode through to the curator endpoint. The default when no episode is given stays 249 (no behavior change for 249). In the `/api/beats/manim_retrigger` per-clip handler, build the design body (`force_regen` + transcript + title + directive) for any episode, not only when the episode equals the old constant — today a non-249 episode gets an empty body and the directive never arrives.
- **Design endpoint:** remove the `episode_249`-only refusal — accept any episode. In the fresh-design branch, fetch the equation catalog for the requested episode (`fetch_episode_equations(ep_num)`) instead of hardcoding "249", and drop the `== "episode_249"` gate. Everything downstream (storyboard, plan write, render, compile) already uses the episode number — verify that at the pulled head and fix any remaining hardcoded "249" in that path.
- **Patch:** generalize `_h2_patch_clip_249` to take the episode (plan path `projects/episode_<ep>/plan.json`, frame assets `chrome_<ep>.png` / `strip_<ep>.mp4`, infographic `<ep>-<n>-infographic.mp4`, master `<ep>-longform-master`). Rename it to `_h2_patch_clip` (keep a thin 249 wrapper only if a caller needs the old name — verify the callers at the pulled head). Patch refuses when the episode's plan or frame assets are missing — it never substitutes another episode's files.
- **Frame assets for 250:** generate `chrome_250.png` + `strip_250.mp4`. They live in `ddma/assets/` alongside the 249 pair. Provenance (verified): the 249 pair was added as binaries in commit 2964c11b (Spec H2 X); NO generator was committed with them and none exists in the repo tree — the strip's design traces to a `strip_v6.py` POC script (named in the assembler's header) that lives outside the repo, most likely in the Windows Desktop POC folders (`249-composite-test-v6\`); look there first. If that script cannot be found, rebuild the pair from the assembler's constants, which fully describe them: chrome = the static footer bar on a 1920x1080 black frame, "Manim" left / "Mosaic" right (Verdana 14, grey 0x888888, at Y=1013); strip = the host-strip loop, 1920x120, 3.0 s loop, SATOSHA / mic / SATOSHI geometry from the v6 design. The contents are episode-independent — the footer center (N/total) is drawn per clip by the assembler, not baked into the chrome — so verify the 250 pair carries no episode-specific text before installing it. A byte copy of the 249 pair under the 250 names is acceptable ONLY after that verification (inspect the image and the strip frames); an unverified copy is a substitution and is forbidden.
